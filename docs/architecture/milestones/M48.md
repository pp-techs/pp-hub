# M48 — Open files in the drive shell

✅ done · superseded in part by the browser-tab opening preference. The rules
in force are in [frontend-conventions.md](../../code-standard/frontend-conventions.md#open-files).

- **Files render in the shell.** `/drive/$spaceId/file/$nodeId`, or
  `/drive/shared/file/$nodeId` for a file shared from outside the caller's
  spaces. `components/file-view.tsx` picks the view by type — block editor,
  OnlyOffice (PDFs included, in its PDF editor), an app's editor, or the
  preview's viewer for image, video, audio and text. On a file route the
  header swaps its breadcrumb for the editor's folder and sub-page trail, and
  its trailing actions carry the file's presence, comments, Share, Versions
  and Download — one header, no second bar.
- **Files use browser tabs, not a second tab strip.** `openFile`
  (`lib/open-file.ts`) is the one way in. Account → Preferences → Opening
  files controls whether it uses the current browser tab (the default) or
  starts a new one. A new browser tab opens `/open/$nodeId`, letting the
  resolver choose the reachable drive route. A popup blocker falls back to
  current-tab navigation.
- **Each file route owns one view.** There is no persisted in-app tab list or
  hidden editor host. While a sub-page link loads, `FileView` alone keeps the
  current markdown editor visible and swaps in the incoming markdown page
  only once it is ready. Other files unmount when the browser leaves them,
  releasing their editor resources and WOPI locks.
- **Compatibility.** `/edit/$nodeId` still redirects through `/open/$nodeId`
  because stored page links, bookmarks and old notification links use it.
