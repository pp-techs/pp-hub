# M48 — Open files in the shell, as tabs

✅ done · part of the [delivery milestones index](../milestones.md). The rules
in force are in [frontend-conventions.md](../../code-standard/frontend-conventions.md#open-files).

- **The problem.** Every document, sheet, board and PDF opened in a new
  browser tab (`window.open('/edit/:id')`, or `/content` for a PDF): a full
  page outside the drive shell, with no rail, no folder trail and one arrow
  back. A morning's work was a row of browser tabs, and the New menu needed a
  blank tab opened inside the click so Safari's popup blocker let it through.
- **Files open in the shell.** `/drive/$spaceId/file/$nodeId`, or
  `/drive/shared/file/$nodeId` for a file shared from outside the caller's
  spaces. `components/file-view.tsx` picks the view by type — block editor,
  OnlyOffice (PDFs included, in its PDF editor), an app's editor, or the
  preview's viewer for image, video, audio and text — under the shell's own header: on a file route the header
  swaps its breadcrumb for a lead slot the editor fills (folder trail, a
  sub-page's trail, name and version line) and its actions land in the usual
  slot. `openFile` (`lib/open-file.ts`) is the one way in, reaching the
  router through the instance `main.tsx` binds; the Safari workaround is
  gone. `/edit/$nodeId` stays as a redirect through `/open/$nodeId`, because
  page links are stored with that href and it is in bookmarks and old
  notification links. The Versions panel moved to the shell, so every
  surface's Versions action has it.
- **Open files are tabs, in a document bar.** The navigation header stays on
  top and stays navigation only: sidebar toggle, where you are, search,
  notifications. Under it a document bar holds the open files as tabs (per
  space, persisted in `ui-store.fileTabs`) and, on the right, the file on
  screen's own controls — version line, presence, outline and comments
  toggles, Share, Versions, Download. A first cut put the tabs above the
  header and the file's name and controls in it; that read as tabs inside a
  browser tab and named the file twice. There is no Drive tab: the rail and
  the breadcrumb lead back. A tab is a real link, so ⌘/Ctrl-click still opens
  a browser tab, and a middle click closes it.
  `FileTabsHost` keeps the five most recently shown files mounted out of
  sight — the document's room, the sheet's frame, the scroll position are
  still there — of which at most two office files, and an office file left
  out of sight for ten minutes is let go, because a mounted OnlyOffice frame
  holds the file's WOPI lock and refuses a version uploaded or saved over
  WebDAV. A page link inside a document and the back button stay in the tab
  on screen; anything else opens a tab beside it.
- **Decisions.** In-app tabs rather than only opening in place: the brief was
  fewer browser tabs _and_ coming back to a file without reloading it. A side
  peek was rejected because OnlyOffice and a board do not fit a panel. The
  sidebar keeps the person's own collapsed/expanded choice on a file.
- **Tested.** `tests/file-tabs.test.ts` holds the tab rules (focus an open
  file, retarget for a page link, insert after the current tab, the
  neighbour on close, the live set and its office cap and idle release).
  Verified in the browser: markdown, OnlyOffice and PDF tabs; the OnlyOffice
  frame is the same element after switching away and back; sub-page links
  and back/forward retarget one tab; close, middle-click close, reload and
  closing the last tab returning to the folder last shown.
- **Not built.** Reordering tabs by drag (a moved iframe reloads), a tab
  overflow menu, and keyboard shortcuts for switching tabs — ⌘W and ⌘1…9
  belong to the browser.
