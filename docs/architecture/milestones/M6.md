# M6 — Trash, move & upload queue

✅ done · part of the [delivery milestones index](../milestones.md).

- **Repairs.** Two handlers existed with no route, so the client's calls 404'd:
  `DELETE /api/v1/nodes/{id}/shares/{shareID}` was never registered, and
  `handleListShared` moved from `/spaces/{spaceID}/shared` to
  **`GET /api/v1/shared`** — the path the client already called (**breaking**
  for the old nested path). `routes_test.go` now walks the router and fails if a
  route the web client calls is missing.
- **Trash lifecycle**, no migration needed: `POST /nodes/{id}/restore`
  (re-parents out of a trashed parent, renames around a live sibling),
  `DELETE /nodes/{id}/purge`, `POST /spaces/{id}/trash/empty` — all owner-only;
  the trash listing carries `location` and `child_count`.
- **Move** (`PATCH /nodes/{id}/move`) exposed in the node menus and selection
  bar via a lazy folder picker.
- **Upload queue**: concurrency 3, per-file progress, cancel/retry/pause, a
  promise-keyed mkdir cache, `webkitGetAsEntry` folder drops, a transfer tray
  mounted in the shell and a depth-counted drop overlay. `XMLHttpRequest`
  because `fetch` exposes no upload progress — the transport was replaced by
  tus in M30.
- Deliberately out of this slice, both requiring migrations: trash retention
  and `deleted_by`. Both landed in M11.
