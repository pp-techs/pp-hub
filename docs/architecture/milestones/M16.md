# M16 — Login → account → space, one shape

✅ done · part of the [delivery milestones index](../milestones.md).

_Settings surfaces superseded by M34_.

- **The space became a URL segment.** `/drive/home|recent|starred` were siblings
  of `/drive/$spaceId`, so `useParams().spaceId` was undefined there and the rail
  emptied itself. They are now child routes of `drive/$spaceId/`, along with
  `shared`, `trash` and `settings/*`; `type DrivePanel`, `onTogglePanel` and
  every `?panel=` value are gone.
- **Membership has one home**: `settings/people` — one table with an Admin
  switch, group chips and pending invitations as rows, beside a group drawer.
  Admin _is_ membership of the `Admin` group, so all three membership mutations
  invalidate `["spaces", id]`; narrowing that to the member list left a promoted
  admin with no chip until reload, which this milestone found and fixed.
- **Settings tabs are routes**, and non-admins are refused in `beforeLoad`
  rather than shown a refusal at a URL that already resolved. `/profile` was
  replaced by `/drive/account/{profile,preferences}` inside the shell.
- **Feeds are per-space, in SQL**: `?space=` on `/recent`, `/starred` and
  `/shared`, because all three are limited and a post-filter hands back a short
  page whenever another space fills the limit. Pinned by
  `internal/httpapi/space_scope_db_test.go`.
- **Deep links survive sign-in**: `/login?redirect=<path>` plus `safeNext`,
  which accepts only a same-origin absolute path (folded into `pp_oidc_tx` in
  M20).
- Cross-space Home was **removed**, not deferred: with every listing scoped to
  one space, a foreign row could not be opened without silently switching the
  rail underneath the user.
- M34 superseded the ten routes and two tab strips; the invariant — the router
  owns which pane is open — still holds.
