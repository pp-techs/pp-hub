# M35 — Instance settings in the admin console

✅ done · part of the [delivery milestones index](../milestones.md).

- `0006_system_config.sql`: `system_config` (key, `tenant_id`, value JSONB,
  `updated_by`), read through `internal/sysconfig` with an in-memory cache,
  per-key validation and environment-variable fallbacks, and each key reported
  with `source: database | env | default`.
- Keys today: `instance_name`, `max_upload_bytes`, `audit_retention_days`,
  `read_audit_retention_days` (M26), `alert_failed_login_threshold` and
  `alert_failed_login_window_minutes` (M26), `default_space_quota_bytes`,
  `version_retention_count` (M30) and `smtp`. Later milestones add their own keys
  with no deploy.
- The mail transport became dynamic here: the SMTP host/port/user/from/TLS and an
  **encrypted** password live in `system_config`, with `password_set` in the
  response instead of the secret. (The `smtp` key is what M31's share
  notifications and M26's alerts send through, so `PP_SMTP_*` is now a fallback,
  not the only configuration.)
- Surface: `/admin/settings` in the console over
  `GET|PATCH /api/v1/admin/settings`, `DELETE /admin/settings/{key}` and
  `POST /admin/settings/smtp/test`; every change writes a `settings_updated`
  security event. Operational policy changes no longer need a container restart.
