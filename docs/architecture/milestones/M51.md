# M51 — Packaged apps

✅ done · part of the [delivery milestones index](../milestones.md). The design
in force is [extensions.md](../extensions.md#packaged-apps-m51); the guide for
authors is [extension-authoring.md](../extension-authoring.md#packaged-apps).

- **The goal.** An extension an instance administrator uploads as a `.zip` in
  Admin › Apps that works at once, with no rebuild — so a third party can ship
  an app without access to the build.
- **The decision.** Sandboxed UI + host data API + optional external backend.
  **No uploaded code runs in the server process.** The UI is static web files
  served under the M50 sandboxing CSP (an opaque origin) and shown in an
  `<iframe>` that talks to the host page only over a `MessageChannel` (bridge
  protocol v1); the host page calls pp-hub for it. Its data is a host-owned
  record store whose access is the node's capabilities. Server logic, when an
  app needs it, runs in the author's own service, reached through a proxy that
  signs a five-minute HS256 token; the backend may call back with that token.
  At first the compiled-in extensions (kanban, checklist) coexisted with it;
  they were later removed and ported to packaged apps
  ([below](#built-in-extensions-removed)). This supersedes, in part, the earlier "out-of-process apps: deferred" and "third
  parties come later" (see [extensions.md](../extensions.md#the-decision)).

## What shipped

### Server

- **Migration `0031_app_packages.sql`**: `ext_packages` (manifest, version,
  digest, size, backend address override, backend secret sealed with AES-GCM
  under `DeriveKey("exthost/backend-secret")`), `ext_package_files` (the files,
  in Postgres rather than the CAS: small, replaced whole in one transaction,
  carried by `pg_dump`) and `ext_records` (keyed `(node_id, id)` so a copy keeps
  record ids; `ON DELETE CASCADE` from nodes; 64 KiB per record enforced by the
  API, a 128 KiB `CHECK` as the merge backstop). Queries in
  `queries/ext_packages.sql`; `InsertExtPackageFiles` is `:copyfrom`, which
  added `CopyFrom` to `store.DBTX`.
- **`internal/apppkg`** — `ParseManifest` and `Read`: the strict packaged
  manifest (unknown fields refused at every level, a compile-time manifest
  named as such) and the zip rules (one top-level directory stripped, `__MACOSX` and
  dot segments skipped, traversal, absolute paths, backslashes, NUL, symlinks
  and duplicates refused; ≤ 20 MiB upload, ≤ 2000 files, ≤ 10 MiB each,
  ≤ 50 MiB in all, counted while inflating), content types by extension, and
  the digest — sha256 over the sorted `path\0sha256(body)\n` lines.
- **`internal/exthost`** — the registry became dynamic (`RWMutex`).
  `packages.go`: `Install` (install or upgrade in one transaction, files by
  `COPY`), `Remove(purge)`, `loadPackages` at `Start` (an unreadable package is
  skipped with a log line), `SetBackendURL`,
  `RotateBackendSecret` (32 random bytes, base64url, returned once),
  `PackageInfo`, `AssetURL`; hooks — `OnCreate` writes a kind's `seed` records
  in the node's transaction, `OnCopy` copies records under the same ids,
  `ValidSubject` accepts `record:<uuid>` of an existing record. `apps.go`: the
  shared runtime under `/api/v1/apps/{appID}/nodes/{nodeID}` — `records`
  (paged list, create), `records/{id}` (get; `PATCH` with `data` or a one-level
  `merge`, `if_rev` → 409; delete, forgetting its comment threads), `events`
  (SSE, topic `app:<id>:<node>`, re-authorized every `StreamRecheck`),
  `broadcast` (≤ 16 KiB, not stored), `people`, `users`, `links`,
  `comments/counts`, `notify` (kind `ext:<id>:<verb>`), `backend/*`; reads
  need `view`, writes `edit`, all behind one decision (installed, node live and
  of the app's kinds, app on for the space, capability held). `backend.go`:
  the proxy (30 s, no redirects, 1 MiB up / 10 MiB down, allowlisted headers,
  no cookies either way; 404 without a backend, 503 until a secret exists),
  `SignToken`/`VerifyToken`, and `MountBackendAPI` at
  `/api/apps/{appID}/nodes/{nodeID}` — outside `/api/v1`, bearer token, API
  rate-limit bucket, re-authorized live on every call.
- **`internal/httpapi/apps.go`** — `POST /api/v1/admin/apps[?upgrade=true][&id=]`
  (multipart `package`; 201 install, 200 upgrade, 409 for an id taken, 400 with the validator's message), `GET|PATCH|DELETE
/api/v1/admin/apps/{id}` (`PATCH {backend_url}`, `DELETE ?purge=true`),
  `POST /api/v1/admin/apps/{id}/backend-secret` → `{secret, app}`; not on the
  MCP agent dispatcher. Audit kinds `app_installed`, `app_upgraded`,
  `app_configured`, `app_removed`. `GET /api/v1/extensions` items gained
  `source` and `package`.
- **Assets** — `appAssetSwitch`, the first middleware (before
  `artifactSwitch`), serves `GET/HEAD /x/<id>/<digest>/<path>` on
  `PP_ARTIFACT_URL`'s host when set (the main host then 404s `/x/`), else on
  `PP_EXTERNAL_URL`; the base comes from `appAssetBase` in `cmd/server/main.go`.
  Each response has the app CSP (`sandbox allow-scripts allow-forms
allow-popups allow-popups-to-escape-sandbox allow-modals allow-downloads`,
  sources limited to the app's own path and the CDN allow-list, `connect-src`
  from `web.connect` or `'none'`, `frame-ancestors` the app's origin), CORS `*`,
  CORP `cross-origin`, `nosniff`, `no-referrer` and immutable caching; a per-IP
  limiter (600/min, burst 200). `/x` joined `apiPrefixes`; the main CSP's
  `img-src` names `PP_ARTIFACT_URL` for app icons.

### Web

- **Registry** (`ext/registry.ts`): the installed packages, `registerPackagedApps`
  on every listing fetch, `useExtRegistry`, `extKindOf`, `extensionById`,
  `allExtensions`.
- **`ext/packaged.tsx`**: the `ExtManifest` from the listing — strings as
  catalog ids `pp-app:<id>:<English>` filled from the manifest's
  `translations`, icons as CSS masks (SVG) or `<img>` (PNG), the editor a lazy
  `AppFrame`.
- **The frame**: `ext/app-frame.tsx`, `ext/app-host.ts` (`attachFrame`, the
  method table, `probeApp`), `ext/app-bridge.ts` (`serveBridge`, param checks).
  An app that is off for the space shows "This app is turned off" before any of
  its code loads. The port is posted once on first load; a second load shows
  "left its page", 15 s without
  `hello` "did not start". The event stream, theme variables, the comment sheet
  (opened from a notification link), `ConfirmDialog` and named toasts come from
  the host.
- **Admin › Apps** (`routes/admin.apps.tsx`): Upload app, a Built in /
  Uploaded badge, and per uploaded app Upload new version…, Backend…, Remove…,
  as better-modal dialogs in `components/apps/` (`upload-app-modal.tsx` with
  folder zipping in `lib/app-package.ts` and the update offer on 409,
  `app-backend-modal.tsx`, `remove-app-modal.tsx`). Security log labels for
  the four kinds; the Vite dev proxy forwards `^/x/`.

### Tooling and SDK

- **`packages/app-sdk`** (`@pp-hub/app-sdk`): the frame SDK (`connect()`,
  `src/index.js` + `.d.ts`), `@pp-hub/app-sdk/server` (`verifyToken`,
  `tokenFromRequest`, `TokenError`), `pp-app.schema.json`, and a README.
- **`tools/pp-apps`**: `init <dir> [--id] [--name]` scaffolds a zero-build
  app with the SDK copied in; `pack <dir> [-o file.zip]` validates with
  `package-manifest.ts` (mirroring `apppkg`), refuses root-absolute asset URLs
  and zips the app.
- **`examples/apps/tasks`**: a zero-build task list — records, live updates,
  assignees through people search and `notify`, per-task comments, read-only
  without edit, `vi` translations.

## Built-in extensions removed

After the packaged-app path shipped, the compile-time mechanism of
[M44](M44.md)–[M46](M46.md) was deleted and Kanban and Checklist became
first-party packaged apps — one path for every app, and no app code with the
server's privileges.

- **Deleted:** `apps/server/extsdk`, `apps/server/ext/{kanban,checklist}`,
  `cmd/server/extensions_gen.go`, the per-extension migration runner
  (`internal/exthost/host.go`, `migrate.go`), `apps/web/src/ext/host.ts` and
  `registry.gen.ts`, `packages/ext-sdk`, `packages/ext-kanban`,
  `packages/ext-checklist`, the root `pp-apps.json`, and the `pp-apps`
  commands `new`, `gen`, `sync`, `check`, `list`, `add` and `remove` (only
  `init` and `pack` remain). `internal/exthost` now hosts packaged apps only
  (`exthost.go`, `packages.go`, `apps.go`, `backend.go`, `discussion.go`,
  `wire.go`); the SPA's registry is built from `GET /api/v1/extensions` alone,
  every listing item carries `package`, and Admin › Apps offers Upload new
  version / Backend / Remove for every app.
- **Added:** `examples/apps/kanban` and `examples/apps/checklist` — React + Vite
  apps against `@pp-hub/app-sdk`, manifest version 2.0.0, same app ids
  (`kanban`, `checklist`) and node kinds (`kanban.board`, `checklist.list`).
  Kanban seeds To do / In progress / Done at positions `11i`, `12i`, `13i`; the
  fractional-position scheme is ported to `src/position.ts` and checked against
  golden values. Validation (30 columns, 50 labels, 5000 cards, 20 links per
  card) runs in the app; the host enforces only the generic record limits.
  Newly assigned people get `assigned` with subject `record:<id>`; card
  comments open the host panel with `comments.open("record:<id>")`. Root
  script `bun run apps:build` builds and packs both into
  `examples/apps/<id>/dist-pack/<id>-2.0.0.zip`. `@pp-hub/app-sdk`'s
  `connect()` now catches the host's handshake at import time and memoizes, so
  calling it from a React effect works.
- **Migration `0032_builtin_apps_to_records.sql`:** converts `ext_kanban`
  (columns, labels, cards with `assignees`, `label_ids`, `link_ids`, `due_at`,
  `rev`) and `ext_checklist` items (`{text, done}`, in their earlier order)
  into `ext_records` under the same ids — collections `columns`, `labels`,
  `cards` and `items`; renames comment-thread and notification subjects
  `card:<id>` → `record:<id>` on `kanban.board` nodes; drops the schemas
  `ext_kanban`, `ext_checklist` and the table `ext_migrations`. `ext_state`
  rows are kept.
- **Operator action:** the apps are **not preinstalled**. After upgrading, an
  instance administrator uploads `kanban-2.0.0.zip` and `checklist-2.0.0.zip`
  in Admin › Apps; the converted boards and checklists open whole and the
  earlier on/off switches come back. Until then they show "not part of this
  installation".

## Smoke

In a browser on the dev stack: upload `examples/apps/tasks` as a `.zip` in
Admin › Apps, switch it on, create a task list from the sidebar (the New dialog
in the manifest's words); the app loads in the sandboxed frame with origin
`null`, cookies and `localStorage` throwing, a direct `fetch` blocked. Add and
tick tasks, see them live in another client, comment on a task. Upgrade
1.0.0 → 1.1.0 (the 409 offered as an update). Set a backend address and
secret; a proxied call verified with `@pp-hub/app-sdk/server`, and a record
written by its callback appearing live. Remove the app (the item shows "not
part of this installation"), reinstall, and the item's data is back.

## Limits

- One process: the event broker and the registry are per process, the
  assumption collaboration rooms already make.
- No server-side validation of record contents beyond shape and size: whoever
  can edit the item can write any record; enforced logic belongs in the app's
  backend.
- No share links to app items. The frame is single-page by
  design.
- Asset files are public by URL — code, not data; the digest makes a URL hard
  to guess, not secret.
- `connect-src` is `'none'` unless declared; the CDN allow-list is
  publishing's (`artifact_cdn_allowlist`).
- **Not in it:** a catalog or signed packages, MCP tools from apps, server-side
  record schemas.
