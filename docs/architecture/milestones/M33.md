# M33 — Membership is a Logto organization

✅ done · part of the [delivery milestones index](../milestones.md).

- Membership used to be defined twice: an operator created the person in Logto so
  they could sign in, then invited the same address into a space. **A Logto
  organization is now the source of truth for who belongs to a company**;
  `spaces.idp_org_id` names the organization a space mirrors, and
  `space_members` is a **projection** of its member list — a table still, because
  ten SQL sites join it and thirteen guards read it, but with exactly one writer.
  The organization role `admin` maps onto the automatic `Admin` group; groups,
  grants, ownership, quota and the Archive are untouched, because a tenant-wide
  template cannot express a per-space group.
- `internal/orgsync` is a Management API client over an in-process
  `client_credentials` token (refreshed ahead of expiry and on 401, paginating on
  `Link`/`Total-Number`), with `ReconcileUser` from sign-in claims and
  `ReconcileOrg` as the job body. Three signals feed it — the ID-token claims,
  the `Organization.Membership.Updated` webhook at `POST /hooks/logto`, and an
  hourly ticker — and **none applies a delta**: each re-reads and converges,
  because webhook payloads arrive unordered. The webhook is mounted outside
  `/api/v1` deliberately, verifies an HMAC-SHA256 of the raw body in constant
  time, enqueues a job and returns 2xx rather than doing the work inline.
- `RemoveMember` split in two: **revocation is immediate** (group rows, then the
  membership row) and sufficient, because content access requires current
  membership; **teardown is confirmed** — `space_departures` queues the
  destructive half behind an admin's decision, because an accidental click in the
  Logto Console must not be irreversible.
- **A space is allowed to have no admin**, which is new and deliberate: pp-hub's
  own write path still refuses to remove the last one (409), but a removal in the
  Console is a fact, not a request. Auto-promoting the owner would invent a
  privilege nobody asked for and break what admin means; the space says so in a
  banner and an instance admin resolves it.
- This superseded the invitation work of M10 and M23 —
  `space_invitations`, the four invitation routes, `POST /invitations/accept`,
  `/invite/$token` and (at the time) `internal/mail` are gone, and an invitation
  is a Logto organization invitation delivered by Logto's email connector.
  Reconciliation also pre-creates `users` rows keyed on `(oidc_iss, oidc_sub)`,
  which **reverses M28's standing rule** that nothing creates an account ahead of
  its owner's first sign-in — right while pp-hub owned identity, wrong once the
  IdP is authoritative.
- Follow-up (`0007_idp_profile.sql`): the IdP also owns the profile. Phone,
  gender and the avatar are mirrored on sign-in and on reconcile; `picture` is
  fetched into the CAS and served from the existing avatar route, so the CSP
  keeps `img-src 'self'`. `avatar_from_idp` records whose avatar it is, so an IdP
  that drops the picture never clears one the person uploaded, on top of the
  real avatar store that M22–M24 put behind the upload.
- **Backfill was considered and refused**: the project is pre-production, linking
  a space is one `UPDATE`, and reconciling an unlinked space is a no-op by design
  rather than emptying it. See [logto-org-sync.md](../logto-org-sync.md).
