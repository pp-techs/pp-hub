# M26 — Audit completeness

✅ done · part of the [delivery milestones index](../milestones.md).

- `0008_read_audit.sql`. Closes the rest of P1 "`activity_events` is a feed, not
  an audit log" on the `security_events` table M21 added, rather than a third one.
- **Reads, deduplicated**: `file_downloaded`, `folder_downloaded`, `file_viewed`
  and `file_opened` (with `detail.mode`) are written where bytes are served —
  `serveBlob`, `serveShareFile`, `handleShareDownload`, `streamZip` and
  `handleEditSession` — after authorisation and before the first byte, for
  signed-in users and share-link visitors alike. Thumbnails, WOPI `GetFile` and
  avatars are not reads. `audit.RecordRead` writes one row per (kind, actor,
  node) per hour from a bounded in-memory map, per replica; when full it forgets
  rather than grows, so its failure mode is an extra row, never a missing one.
- `security_events.node_id` (indexed, **no FK**, so a purge cannot erase the
  record) makes "who read folder X" a subtree filter over live, trashed and
  purged nodes; read kinds purge on their own `read_audit_retention_days` (90).
- `GET /api/v1/admin/security-events` takes `?kind=&node=&from=&to=` (RFC 3339,
  `to` exclusive, malformed → 400) and `/export` streams the same filters as CSV
  — BOM, formula-injection guard, keyset paging — itself a `security_log_exported`
  event.
- **Alerting**: `internal/alert` scans every minute for addresses with
  `alert_failed_login_threshold` (10) failures inside
  `alert_failed_login_window_minutes` (15), writing one `security_alert` row per
  window and mailing every live instance admin through the job queue. Only one
  rule ships, because a failed sign-in usually carries no user to key on.
