# M17 — One dialog owns access

✅ done · part of the [delivery milestones index](../milestones.md).

- Sharing was split across two dialogs that each answered half the question, and
  the split was client-side invention: the server had always allowed a file to be
  granted to a group, and only the UI refused to offer it. Both are now one
  `share-dialog.tsx` on any node — groups, people and the public link in one
  merged access list with one level/download/re-share control.
  `?panel=share` is gone; `PanelKind` is just `versions`.
- **Grantees come from the space, never from a tenant-wide directory.** One
  `grantee-picker.tsx` offers the space's groups above its members, filtered
  locally from endpoints that are already cached. This closed a leak:
  `GET /users/search` had no space scoping, so any signed-in user could
  enumerate every account on the instance. It now joins `space_members` against
  the caller (lifted for an instance admin), pinned by
  `SearchIsLimitedToSharedSpaces`.
- **The shared-folder indicator read the wrong list** — `GET /shared` is
  _shared with me_, which excludes everything the caller owns. It is now a
  server-set `node.shared` resolved by `NodesWithLiveShares` in the same batch
  as caps, and it changes the glyph rather than stamping an overlay on an icon
  that already means something.
- **Fixed on the way**: base-ui's `Menu` popup runs a bubble-phase keydown
  handler that calls `preventDefault()` on printable keys for typeahead, so an
  `<Input>` inside a dropdown lost every keystroke while keeping focus. The input
  now stops propagation (Escape excepted).
