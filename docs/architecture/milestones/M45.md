# M45 — Kanban core

First extension on the [M44](M44.md) host; design in [extensions.md](../extensions.md#kanban--ext_kanban).

## What shipped

- **`apps/server/ext/kanban`** (uses `extsdk` only). A board is a `kanban.board`
  node. Migration `0001_init.sql` in schema `ext_kanban`: `columns`, `labels`,
  `cards`, `card_assignees` (indexed by user for a later "assigned to me"
  view), `card_labels`. A new board is seeded with To do / In progress / Done in
  its creating transaction.
- **Positions** are fractional-index strings ordered bytewise (`COLLATE "C"`):
  `Between` halves the gap, `After` appends with a counter key that grows by a
  letter only when its digits run out, `Spread` renumbers. A move writes one
  row; a key past 48 letters renumbers the list and the event is `reload`.
  Writes to one column's order take a row lock on that column.
- **Routes** under `/api/v1/ext/kanban/boards/{nodeID}`: snapshot, SSE
  `/events`, `/people`, columns (create, rename, WIP limit, move, delete with
  `move_to`), cards (create, edit with `if_rev`, move, delete), labels. View
  reads, edit writes; limits 30 columns, 50 labels, 5000 cards per board.
- **Concurrency.** Every card write bumps `rev`; an edit carries `if_rev` and a
  stale one is 409. A move does not carry one: it writes position and column
  only. Two people moving different cards never touch the same row.
- **Realtime.** After commit the handler publishes `board:<id>` events
  (`card.upsert`, `card.delete`, `column.upsert`, `label.upsert`,
  `label.delete`, `reload`); the SPA applies them to the query cache. The stream
  re-resolves access every minute and closes on revocation, trash, switch-off or
  sign-out.
- **Copy** (`OnCopy`, one statement) copies columns, labels, cards, their labels
  and links — not assignees and not comments. **Purge** cascades through the
  `nodes` foreign keys.
- **Assignees** must hold view on the board (`Caps`), so an assignment cannot
  hand someone a card they cannot open.
- **Board screen** follows the Stitch designs (screen ids in
  `.stitch/SCREEN-PROMPTS.md`; the exported renders are not kept in git). A toolbar under the header filters the board
  in the browser by text (title and description), assignee (anyone on a card
  here, or unassigned), label (any of the chosen) and due date (overdue, next
  seven days, none); the filter changes only what is drawn, a column's count
  and WIP badge still count every card, and nothing is saved or shared. Column
  headers carry a count pill, a quick-add `+`, an amber badge at the WIP limit
  and a red one over it; a drop shows a line with end dots; an empty column,
  an empty board (a dismissible "Plan work on this board" note, remembered per
  browser) and a view-only board (a banner) say what they are. Pure filter logic
  is `matchesFilter` in `board-state.ts`. Not built, because the app has no such
  data: breadcrumbs, presence avatars, card keys, "request edit access".
