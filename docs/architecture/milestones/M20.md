# M20 — Sessions are rows

✅ done · part of the [delivery milestones index](../milestones.md).

- `0002_sessions.sql`, the first file on top of the frozen baseline. The cookie
  used to be `v1.<uuid>.<expiry>.<hmac>`: self-contained, hard-coded to thirty
  days, backed by nothing, so nothing could be revoked and the only lever —
  rotating `PP_SESSION_KEY` — signed out every user and rotated the WOPI signing
  key with them.
- The cookie is now an opaque 256-bit token whose SHA-256 is the `sessions` row,
  and `GetSessionByHash` resolves cookie → session + owner in one indexed join.
  Idle deadline 30 days slid at most hourly per session, 90-day absolute cap from
  `created_at`, five-minute purge ticker (`GetSessionByHash` filters on
  `expires_at` itself, so a purge is housekeeping rather than enforcement).
- `users.last_seen` finally means last seen: `TouchSession` writes it in the same
  statement that slides the deadline.
- **Revocation became a surface**: list / delete one / delete all but the current,
  backing the account tab M16 recorded as not built, with the user id in every
  delete predicate. Revoking the current session also clears the cookie.
  `POST /auth/logout` deletes the row and returns `end_session_url`, and the web
  sign-out hands the browser to it — with the global 401 handler disabled before
  the cross-origin assignment, because a refetch into the revoked session would
  otherwise land on `/login` with the IdP session still standing.
- **Authentication is a middleware on the `/api/v1` group**, replacing ~30
  hand-written guards that nothing but eyesight kept in step with ~70 handlers;
  handlers call `caller(r)`, which cannot be nil, and calling it outside the
  group panics as a wiring bug. `TestEveryAPIRouteIsAuthenticated` walks the
  router. Suspension is still per request (403, not 401).
- **The handshake is single-use and constant-time**: one `pp_oidc_tx` cookie
  carrying state, nonce, PKCE (S256) verifier and destination, cleared
  unconditionally at the top of the callback; the pair it replaced survived every
  failure path for ten minutes, which is a replay window for nothing. Failures
  redirect to `/login?error=<code>`, because the callback is a navigation and a
  problem+json body would render as raw JSON.
- Cookies carry `Secure` when `PP_EXTERNAL_URL` is `https://`; split-horizon OIDC
  is real (`PP_OIDC_ISSUER` is what the process reaches,
  `PP_OIDC_ISSUER_EXTERNAL` what the browser is sent to); and changing the issuer
  no longer 500s every returning user — a miss on `(oidc_iss, oidc_sub)` falls
  back to the **verified** email and re-points the account (`AdoptUserIdentity`).
- `config.SessionKey` became `SecretKey` with HKDF-SHA256 subkeys per purpose
  (WOPI takes `wopi.KeyPurpose`); the env var stays `PP_SESSION_KEY` on purpose,
  since renaming it would silently fall back to an ephemeral key in every
  deployment. Sessions no longer touch it.
- The thin second identity endpoint is deleted: `GET /api/v1/users/me` is the one
  identity endpoint, cached under `keys.me`, plus a global 401 handler in
  `main.tsx`.
- **The verified-email rule was asymmetric**: the adoption path in `resolveUser`
  always required `email_verified`, but the ordinary path rewrote `users.email`
  from the claim on every sign-in — and that column is what a direct share is
  granted to, what member-add resolves an address against, and what
  `PP_BOOTSTRAP_ADMIN_EMAIL` is compared to. Both paths require verification now,
  and admin promotion requires it separately.
