# M41 — Agent access over MCP

✅ done · part of the [delivery milestones index](../milestones.md). The design
in force is [agent-access.md](../agent-access.md).

- **The decision.** Chat-app agents (Claude.ai, Claude Desktop, ChatGPT) have no
  shell, so a skill + CLI cannot reach them; a remote MCP server can. It lives in
  `apps/server` (`internal/httpapi/mcp.go`, official `modelcontextprotocol/go-sdk`,
  Streamable HTTP, stateless) at `${PP_EXTERNAL_URL}/mcp/`, and the agent acts as
  the signed-in person — never a service account.
- **Logto is the authorization server; pp-hub only verifies.** Clients identify
  with a Client ID Metadata Document (CIMD), which Logto ships from 1.43.0 and
  `pp-logto-setup.sh` now switches on, together with the API resource
  `${PP_EXTERNAL_URL}/mcp/`. No Logto scope, role or default role: the token only
  proves the person and the audience. Confirmed live before shipping — a CIMD
  client (Claude Code's document) signed in through Logto, consented, and received
  an `at+jwt` with `aud` = the resource and `scope: ""`; its refresh rotated.
- **Per request** (`mcpBearer`): the instance switch `mcp_enabled`, the bearer
  token (`auth.Service.VerifyAccessToken`: JWKS, issuer, exact audience, expiry),
  the account by `(oidc_iss, oidc_sub)` — never created here — suspension, the
  person's `agents_enabled`, a per-person rate limit (1200/min), and
  `audit.WithAgent` on the context. `/.well-known/oauth-protected-resource[/mcp]`
  serves RFC 9728 metadata; a 401 points at it.
- **One rule set.** `internal/agenttools` holds the registry (25 tools, a 26th —
  `create_public_link` — only under `mcp_public_links`), and each tool is a few
  REST calls. `agentAPI` answers them in process through `apiRoutes`, the same
  table the network mounts, so an agent runs the web client's handlers:
  capabilities, audit rows, notifications. The embedded agent planned next will
  call the same registry.
- **Documents.** Two routes only the agent router mounts: `GET /nodes/{id}/text`
  (view; flushes an open room first via the new `collab.Service.Flush`; etag =
  current blob hash) and `PUT /nodes/{id}/text` (edit; through `collab.Reseed`,
  so a stale `base_etag` is a 409 and an accepted write reaches the room live).
  `add_comment` anchors a thread by marking the quote in the parsed tree and
  rendering it with `mdoc` (`agenttools.AnchorComment`).
- **Switches and UI.** `system_config` `mcp_enabled`, `mcp_public_links` (both
  off by default) and `mcp_tokens` (on), in Admin › Settings › Agent access;
  `users.settings.agents_enabled` and the connector URL (`GET /users/me` →
  `mcp_url`) in Settings › Security.
- **Personal access tokens**, beside OAuth, for clients configured from a file
  (`.mcp.json`), CI and scripts. `agent_tokens` (migration `0018`) stores only
  the SHA-256 of `pph_…`; a lifetime of 1–90 days is fixed at creation;
  `GET|POST|DELETE /users/me/agent-tokens` are mounted on the network's
  `/api/v1` only — never on the agent router, nor are the session routes — and
  the token acts through the same switches, suspension check and rate limit,
  audited as `client_id: pat:<id>`.
- **Edges.** nginx `location /mcp/`, `= /mcp` and
  `/.well-known/oauth-protected-resource`; the same in the Vite dev proxy.
- **Tests.** `mcp_db_test.go` (a fake issuer signs real JWTs; the SDK is the
  client): bearer-only, both switches, access and stale-write refusals plus a live
  room receiving the write, comment anchoring, public links opt-in, personal
  tokens end to end; `agenttools/anchor_test.go` for anchoring and its refusals.
- **Not in it:** binary upload, folder/file management, office/PDF text,
  admin operations, the embedded agent, a CLI.
