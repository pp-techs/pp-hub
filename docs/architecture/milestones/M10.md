# M10 — Space settings & admin console

✅ done · part of the [delivery milestones index](../milestones.md).

- `spaces` gained slug / description / default_role / archived_at, plus
  `space_invitations` and `users.suspended_at`. `default_role` went in M15 and
  the invitation half in M33.
- Invitations existed because `space_members.user_id` references a user row and
  an invited address may have no account: only the token hash was stored, the
  plaintext was shown once, and re-inviting an address **replaced** the pending
  row. Accepting checked that the invitation's address matched the signed-in
  account; an address that already had an account was added as a member directly.
- **Suspension is enforced on every request**, not at sign-in, and answers 403
  rather than 401 — the credentials are fine, the account is not. An admin
  cannot revoke their own admin flag or suspend themselves. The check moved from
  per-handler guards into the `/api/v1` middleware in M20.
- Surface: `?panel=settings` with General/Members/Danger tabs, `/invite/$token`,
  a rewritten admin console with stat tiles and suspend/reinstate — **the panel
  and Members tab were replaced in M16**, then the routes in M34.
- **Fixed after the fact**: `spaceDTO` never carried slug/description/
  `default_role`, so the form read them back empty and cleared them on save; two
  better-modal dialogs held `useState` across reopenings (now `useKeyedState`).
- **Not done, and why**: the Sharing / Storage / Integrations settings panes had
  no server behind them, so they were omitted rather than shipped empty.
