# M50 — Publishing

✅ done · part of the [delivery milestones index](../milestones.md). The design
in force is [publishing.md](../publishing.md).

- **The decision.** An `.html` file or a folder becomes a public mini web site,
  the way an AI chat shares an artifact. Member-made HTML can never be served
  from `PP_EXTERNAL_URL` as an ordinary page, because there it would be stored
  XSS against the session. So the bytes come from a separate artifact router in
  the same `server` process, selected by the main router's first middleware:
  by default by the path prefix `/a` on the app's origin (`publish.SamePath`,
  stripped, so none of the app's headers, session or routes apply), or, with
  the optional `PP_ARTIFACT_URL`, by `Host` on a second origin. Every response
  there carries a CSP `sandbox` (scripts yes, same origin never) with
  `connect-src 'none'` and an admin CDN allowlist, and the viewer `/p/<token>`
  frames it. On the app's origin that header alone guards the session — a
  proxy or browser that drops it runs the page as the viewer — so a separate
  origin is the recommended hardening for untrusted publishers.
- **Snapshot, not live.** Publishing writes a manifest of `path → blob_hash`
  (`publication_files`) over bytes already in the CAS. Republish replaces it
  and bumps `rev`, and the URL stays the same. Blob references and space usage
  are counted by triggers, the way versions are.
- **Switches.** Publishing needs only the instance switch `artifacts_enabled`,
  off by default. `PP_ARTIFACT_URL` is optional; when set it must be a
  different host from `PP_EXTERNAL_URL`, and `/a/` on the main host is then a
  plain 404. `GET /api/v1/users/me` reports `publishing_isolated` (true only
  with it), and Admin › Settings › Sharing › Publishing shows a warning
  ("Published sites share this address") when it is false. The allowlist is
  `artifact_cdn_allowlist`, in Admin › Settings › Sharing. Publishing also
  needs what a downloadable public link needs on the source.
- **Link, password, expiry.** The token is the share link's 16 base62
  characters. It is looked up by hash and also sealed, so the dialog can show
  the URL again. A password is PBKDF2-SHA256. `unlock` mints a 12 h HMAC grant
  that is bound to the `rev` and carried in the path, because a sandboxed frame
  has no cookies. Expiry, the switches, `allow_public_links`, an archived space
  and the creator's membership are re-checked on every request. Any of them
  failing answers 404 on both origins.
- **Routes.** `GET/POST/PATCH/DELETE /api/v1/nodes/{id}/publication`;
  `GET /p/{token}` and `POST /p/{token}/unlock` (Accept split like `/s/`); the
  artifact router's `GET/HEAD /<token>/[~<grant>/]<path>`, under `/a` on the
  app's origin or at the root of `PP_ARTIFACT_URL`. Slash redirects send a
  relative `Location`.
- **Agents.** `publish_artifact` (files as UTF-8 or base64, at most 8 MiB, written
  into a folder through the agent-only `PUT /nodes/{id}/site-files`) and
  `unpublish_artifact`. They are offered only when `mcp_public_links` is on too.
- **Web.** `Publish…` in `nodeActions()` for `.html`/`.htm` files and folders,
  opening a better-modal dialog (`publish-dialog.tsx`). The viewer is
  `routes/p/$token.tsx`. The Admin › Settings › Sharing › Publishing section
  holds the switch and the allowlist.
- **Migration** `0030_publications.sql`.
- **Tests.**
  - Router and headers (`httpapi/artifact_test.go`): the two routers never
    answer each other's paths (including `/a/` on the main host with a
    separate artifact host), the CSP is on every artifact response, the main
    CSP frames the artifact origin, and the log redaction.
  - Model (`publish/publish_test.go`): path normalization, password, grant and
    sealing.
  - End to end (`httpapi/publish_db_test.go`): lifecycle with `ref_count` and
    used bytes, ETag/Range/gzip, the grant bound to `rev`, a wrong password
    answering 422, the switches and expiry answering 404, a folder with no entry
    answering 422, and the MCP tool's gating and republish in place;
    `TestPublishOnTheAppOrigin` serves a publication under `/a/` with the same
    sandbox, the prefix kept by the CSP and every redirect, and nothing under
    `/a/` reaching the app.
- **Not in it:** rendering markdown as pages, `.zip` upload, custom domains, SPA
  fallback routing, third-party embedding, view counts, publishing to members
  or guests only, a list of a space's publications.
