# M25 — Observability

✅ done · part of the [delivery milestones index](../milestones.md).

- Endpoints only: no tracing, no error tracking, no bundled Prometheus or
  Grafana — an operator points their own at the listener.
- `internal/obs.InitLogging` is the first statement of `run()` in both binaries
  and installs one `slog` handler (`PP_LOG_LEVEL`, `PP_LOG_FORMAT`; `json` in
  prod), stamping chi's request id on every record whose context carries one, so
  a user report, its access-log line and its `security_events` row join on one
  value. An unusable value warns and falls back rather than refusing startup.
- `Server.observe` replaces chi's `Logger` and `Recoverer`: one record per
  request with method, redacted path, route pattern, status, bytes, duration,
  client address and `user_id`; DEBUG for `/healthz` and `/readyz`, ERROR for
  5xx. Panics log a stack and answer problem+json 500.
- Metrics on a second listener, `PP_METRICS_ADDR` (`:9091`, `off` disables),
  serving only `/metrics`: HTTP by method/route/status and duration (buckets to
  300s, because downloads stream for minutes; `route` is always a chi pattern or
  `unmatched`, never a raw path), pgx pool stats, `pphub_jobs{kind,status}` and
  oldest pending age, referenced vs awaiting-GC blobs, and Go/process collectors.
  It starts before OIDC discovery so a server stuck at its IdP is scrapeable, and
  a bind failure is logged rather than fatal.
- `cmd/worker` deliberately has no metrics listener — it has no port by design —
  and its backlog is visible from the server through `pphub_jobs`.
