# M19 — One owner decides where a write lands

✅ done · part of the [delivery milestones index](../milestones.md).

- The rail's New menu is a sibling of the listing and used to guess the space
  root, so uploading from inside a folder silently landed at the top.
  `DriveWriteProvider` is now the sole owner of the destination, mounted above
  both, and `writeTarget` derives it from `?dir=`. A surface with no `?dir=`
  writes to the space root by definition, not by fallback.
- The provider also owns both hidden file inputs (`webkitdirectory` is a
  property of the element, so picking files and picking a folder cannot share
  one control) and the New-folder dialog; `ui-store.newFolderOpen` is gone.
- `folderActions()` is `nodeActions()` for the folder itself, rendered by the
  rail dropdown and by a background `ContextMenu` whose trigger is the scroller,
  so it answers on the gaps between rows and over the empty state. A background
  right-click also clears the selection.
- Paste needs a source: a small `ui-store.clipboard`, deliberately outside
  `partialize` so it never survives a reload. `pasteTargets` refuses cutting a
  node into the folder it already sits in or into its own subtree, while a copy
  into the original's folder stays offered. `tests/write-target.test.ts` covers
  the arithmetic.
- **The space root is a subject, not a hole** (shipped later, same area):
  `DetailsPanel` takes a `DetailsSubject` — `{kind:"nodes"}` or `{kind:"space"}` —
  and renders a space sheet at the root (name, description, storage against
  quota, member count, your access). Every breadcrumb but the last is a link now,
  so there is a way back to the top of the space through the header.
- Drag-and-drop relocation of nodes landed later on the same `Move` endpoint.
