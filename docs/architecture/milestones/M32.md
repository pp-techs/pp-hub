# M32 — The UI speaks more than one language

✅ done · part of the [delivery milestones index](../milestones.md).

- English and Vietnamese through Lingui, with gettext `.po` catalogs compiled by
  `@lingui/vite-plugin`, so there is no runtime ICU parser and no catalog fetch.
  See [i18n.md](../i18n.md).
- Three decisions carry it: **message ids are hashed from the source text**, so
  migrating ~900 inline strings cost no key-naming and Weblate still shows
  `New folder` as the `msgid`; **language is an account preference, not a device
  one**, stored in `users.settings` and read off `GET /users/me` with a partial
  `PATCH /users/me/preferences`, and mirrored into `localStorage` so the first
  frame does not flash English; and **module-scope label maps hold
  `MessageDescriptor`s, never rendered text**, with
  `lingui/t-call-in-function` an error so nobody rediscovers why.
- Fragment-spliced sentences became single ICU messages, because word order is
  not English's to lend. OnlyOffice follows through `?ui=<locale>` resolved into
  `editorConfig.lang`, and the editor also follows the app theme; translation
  runs in a self-hosted Weblate provisioned by `deploy/weblate/`.
  `apps/web/tests/catalogs.test.ts` holds the invariant Weblate cannot: balanced
  ICU braces and a matching placeholder set.
- Deliberately out: **the server is still English only** — problem+json details,
  `/login?error=` codes and Logto's own invitation template — though the client
  already turns those codes into translated sentences.
