# M27 — Content-indexed search

✅ done · part of the [delivery milestones index](../milestones.md).

Shipped in two halves under one number: markdown and plain text first, then PDFs
and office documents.

- What asked for it: P1, "Search only matches file names" in
  [production-readiness.md](../production-readiness.md). People search for the
  sentence in a contract or the line in a payroll sheet, not for its file name.
- Schema: `0016_content_search.sql` — `node_texts`, one row per file holding the
  text of its **current** version, `folded` for accent-insensitive Vietnamese
  and a generated `tsv` ([data-model.md](../data-model.md)). Search joins on
  `node_version_id = nodes.current_version_id`, so a row that has not caught up
  is not matched rather than served stale; the upsert is guarded the same way,
  so a late job for a superseded version writes nothing.
- `GET /api/v1/search` merges name and content matches — every name hit above
  every content-only hit, `ts_rank` within content — and each item says
  `match: "name" | "content"` with a `snippet` and `snippet_highlights`.
- **Three extraction kinds, one table.** The kind is a routing key like a render
  kind ([preview-pipeline.md](../preview-pipeline.md#text-extraction)), so what
  runs where follows what each extractor needs:

  | Kind             | Types                                 | Reads with                         | Runs in      |
  | ---------------- | ------------------------------------- | ---------------------------------- | ------------ |
  | `extract:text`   | `text/markdown`, `text/plain`         | `mdoc.PlainText` / verbatim        | `cmd/server` |
  | `extract:pdf`    | `application/pdf`                     | `pdftotext`                        | `cmd/worker` |
  | `extract:office` | every type `render:office` thumbnails | OnlyOffice → PDF, then `pdftotext` | `cmd/worker` |

- **Decision: office text is read from the converted PDF.** One path serves
  documents, spreadsheets and slides, including the legacy binary formats
  (`.doc`, `.xls`, `.ppt`) that a pure-Go OOXML reader would not open, and the
  conversion shares the thumbnail's cache key (the blob hash), so whichever job
  runs second is a cache hit in OnlyOffice. The cost: a spreadsheet is read as
  it would print — cells outside the print area and hidden sheets are not
  indexed.
- **Decision: no text is a result, not a failure.** A scanned PDF yields an
  empty `node_texts` row, so the file counts as indexed and the backfill does
  not requeue it. A corrupt PDF fails like any job. OCR is not attempted.
- **Decision: a long document is cut, not failed.** `runText` stops reading and
  kills `pdftotext` once it has 1 MiB (the index keeps 256 KiB after
  normalising); a deadline hit before that is an error, because the text read
  so far would be an arbitrary prefix of an unfinished walk.
- Both worker extractors decline to register when they cannot work, as the
  renderers do — `pdftotext` missing, or for office also OnlyOffice, the WOPI
  address or a shared `PP_SESSION_KEY` — so their jobs wait for a worker that
  can. `extract:office` fetches its own source (`FetchesOwnSource`): the
  dispatcher does not open the blob for it.
- `extractableMimes` is built from `officeMimes`, so a type that gets an office
  thumbnail is indexed and the two lists cannot drift. A restored version is
  re-indexed from its version row alone, with no file name, so the converter
  takes the file type from the MIME type when the name has no extension.
- Backfill is unchanged: `cmd/server` queues every unindexed current version at
  startup, whatever its kind; PDF and office jobs wait until a worker with the
  right extractor claims them.
- No migration beyond `0016`; no new setting; the worker image already carries
  `pdftotext` (poppler-utils).
- Tests: `preview/extract_binary_test.go` (kind mapping, `runText` caps and
  failures, `pdftotext` on a generated PDF — skipped without poppler — the
  dispatcher with recording extractors for both kinds, backfill, jobs waiting
  without an extractor), `extract_db_test.go`, `render_office_test.go`
  (file type from MIME); `TestOfficeAgainstRealOnlyOffice` now signs with
  `PP_TEST_ONLYOFFICE_JWT_SECRET` and checks the converted PDF's text.
  Smoke on the dev stack with the new worker image: the 14 PDFs and office files
  already in the drive were indexed from the server's startup backfill —
  Vietnamese spreadsheet and PDF text included — and matched without accents;
  scans and blank documents indexed as empty.
- What it deliberately did not build: OCR for scanned PDFs, text from other
  formats (`.rtf`, `.csv`, `.epub`, archives), and per-sheet or per-page
  locations in a snippet.
