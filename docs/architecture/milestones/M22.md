# M22 — Backup and restore

✅ done · part of the [delivery milestones index](../milestones.md).

- `deploy/backup/pp-backup.sh` and `pp-restore.sh`, POSIX `sh` driving
  `docker compose` — no volume name is ever hardcoded, since the compose file
  carries no top-level `name:`.
- **Postgres is dumped before blobs are archived, never the reverse**: the one
  ordering that must never invert is a blob a fresh row already references but
  whose bytes missed the archive. Both artifacts are verified (`pg_restore
--list`, `tar -tzf`) before the script calls itself done; retention defaults to
  14 days; the restore verifies the archive before stopping anything and polls
  `/readyz` for 60s on the way back.
- `.env.prod` is explicitly out of scope and the script says so on every run: a
  restore without it comes up as a different instance.
- **A restore has actually been performed** against a built `compose.prod.yml`
  stack — drill row and marker blob written, backed up, destroyed
  (`DROP SCHEMA public CASCADE`, `rm -rf /data/blobs/*`), restored, and
  `schema_migrations`' newest version matched.
