# M40 — Block documents, completed

✅ done · part of the [delivery milestones index](../milestones.md).

- What asked for it: M39 shipped the editor and live co-editing, and left a
  document with no way to be read outside the editor, taken out of pp-hub with
  its images, started from anything but a blank page, or discussed. This
  closes those; comments themselves are [M29](M29.md), which shipped with it.
  The design is [block-documents.md](../block-documents.md).
- **Decision: one server-side reading of a version.** `internal/blockdoc`
  parses a version (16 MiB cap, `blockdoc.MaxBytes`) for every consumer
  outside a room: `GET /nodes/{id}/document[?version=]` answers
  `{doc, lossy, version}` under `CapDownload`, and the web renders it with one
  read-only component, `components/markdown-document-view`, built on
  `createMdocKit` with the editor's node views — used by the preview panel,
  the version preview modal (with **Restore**) and the share page.
- **Decision: a link renders, never edits.** `/s/{token}/document` and
  `/s/{token}/attachments/{hash}` take the link's download permission and
  coverage, the same terms as its other byte routes.
- **Export** — `GET /nodes/{id}/export`: a zip of the markdown with every held
  `attachment:<hash>` rewritten to `assets/<unique filename>` plus those
  files; `CapDownload`, audited as a download; **Export with images (.zip)**
  in node actions and the editor header.
- **Templates** — five (meeting notes, outline, project spec, runbook, weekly
  report) in English and Vietnamese under `internal/blockdoc/templates/`,
  listed by `GET /templates/markdown` and applied by `"template"` on
  `POST /spaces/{id}/documents`. They are canonical `mdoc.Render` output, so a
  new document is editable, not lossy, and not rewritten by its first save.
- **Decision: link bookmarks are fetched by the server, SSRF-safe by
  construction.** `POST /nodes/{docId}/unfurl` (`CapEdit`) runs
  `internal/unfurl`: the destination is checked at dial time on every attempt
  and redirect (private, loopback, link-local, metadata refused), environment
  proxies ignored, http/https only, 5 s, 1 MiB of HTML, a sniffed preview image
  of at most 5 MiB stored as the document's attachment under the usual caps
  and quota — never hotlinked (CSP `img-src 'self'`).
- **Block set** grows by `video`, `embed` (bookmark) and `mention`
  (`user:<uuid>` / `doc:<uuid>`), all serialized by slash-editor, and the
  `comment` mark, which slash-editor drops and `internal/mdoc` alone persists
  as an invisible HTML-comment marker pair (format in `mdoc.go`). New pure
  helpers: `Attachments`, `Mentions`, `PlainText`, `MapAttachments`. Fixtures
  grew from 121 to 169, plus the Go-only comment cases.
- **Write-back adopts attachments** a pasted image or file references but the
  document does not hold, from a live document the writer may download; best
  effort, never failing the write-back. The attachments route serves video
  inline with `Range`.
- **Fix: stale collab locks are cleared only after the listener binds**
  (`listenThenStart` in `cmd/server`): a second copy started by mistake used to
  strip the running process's rooms of their locks before failing to bind.
- Web: presence colours and initials stable per user; image alt text from the
  file name; narrow-screen layout; table controls; outline panel; @mentions
  of members and documents; video and embed node views with a link modal;
  template picker; the node header refreshing every 30 s so a markdown
  document's version number follows write-backs.
- No migration of its own; `0013`/`0014` are M39's, `0015` M29's, `0016`
  M27's.
- Tests: `internal/httpapi/documents_db_test.go`, `documents_test.go`
  (`forwardSeeker`), `blockdoc/templates_test.go`, `unfurl/unfurl_test.go`,
  `mdoc/comment_test.go`, `mdoc/helpers_test.go`, `cmd/server/main_test.go`,
  web `presence.test.ts`. Browser smoke on a cloned database: template
  creation, outline, table controls, share-link render, export zip.
