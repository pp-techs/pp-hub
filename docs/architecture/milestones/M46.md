# M46 — Kanban collaboration

✅ done · part of the [delivery milestones index](../milestones.md).
Builds on [M45](M45.md); comments are [M29](M29.md)'s.

## What shipped

- **Discussion on a card.** Migration `0024`: `comment_threads.subject`
  (`card:<uuid>`; null on a document, whose text anchors its threads). The
  existing comment routes work on an extension node: `GET
/nodes/{id}/comments?subject=` and `POST /nodes/{id}/comment-threads` take the
  subject, which the node's extension validates (`NodeKind.ValidSubject`: the
  card must be on this board); a document takes none. Reply, resolve, edit and
  delete are unchanged. Taking part takes **view** on the node. Mentions and
  the owner's comment notification are M29's.
- **Counts and clean-up.** `Host.Comments().Counts` feeds the badge on a card;
  deleting a card calls `Forget`, which deletes its threads. Threads cascade
  with the node on purge.
- **Assignment notification.** `Host.Notify().Send` writes
  `ext:kanban:assigned` (the card title as excerpt, the card as `subject`,
  migration `0024` adds `notifications.subject`), only for someone who can open
  the board and is not the actor, only for people newly assigned, and pushes it
  to their open tabs. The notification DTO carries `subject`, which opens the
  card.
- **Links to drive files.** Kanban migration `0002_card_links.sql`. A card holds
  up to 20 links to nodes **in the board's space**; the writer must be able to
  open each (409 otherwise), and a card cannot link its own board. The link is
  re-resolved per viewer through `Host.Resolve` on every REST read: someone
  without access to the target sees `accessible: false` and no name. The
  broadcast event carries `link_ids` only — one viewer's resolution must not
  reach another — and a client whose cached ids differ refetches.
